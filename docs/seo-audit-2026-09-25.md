Measured on **production** (`https://amargupta.tech`) between 13:52 and 14:25 UTC. Spec: `docs/specs/seo-audit.md`.

checklist: status codes, social images, where Googlebot finds the metadata, and mobile layout. Each item below is
measured, not taken from a checklist.

## What is already right (measured)

- Lighthouse **SEO 100** on all 7 pages × mobile and desktop, except #15.
- Every page has exactly one `<h1>`, a title, a meta description, a self-referencing canonical and `index, follow`.
- JSON-LD: `WebSite` + `Person` on every page; `Article` on posts and projects. Posts lack none of Google's
  recommended Article fields (`headline`, `image`, `datePublished`, `dateModified`, `author`).
- `http://` → `https://` 308; `/blog/` → `/blog` 308; `robots.txt` is `Allow: /` with the sitemap listed.
- No `<img>` without `alt` on any audited page. The newest post is linked from both `/blog` and `/`.

## Sources for the causes

- #1, #3: Next 16.2.3's bundled docs, `01-app/03-api-reference/03-file-conventions/loading.md` § "Status Codes":
  *"When streaming, a `200` status code will be returned … Next.js includes a `<meta name="robots"
  content="noindex">` tag … If you need a 404 status … ensure the resource exists before the response body is
  streamed."* Streaming starts *"when a Suspense fallback renders (for example, a `loading.tsx`)"*. The Googlebot
  split is `node_modules/next/dist/shared/lib/router/utils/is-bot.js` (`HEADLESS_BROWSER_BOT_UA_RE`).
- #2: `generate-metadata.md`: *"File-based metadata has the higher priority and will override the `metadata`
  object and `generateMetadata` function"*, so `blog/[slug]/opengraph-image.tsx` gives every post its own image.
